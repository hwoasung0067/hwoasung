# 피드백 처리
1. input/feedback에 원문 또는 명시적 발췌로 보존. 전체 원문이 아니면 반드시 범위를 밝힘.
2. .ai_history/feedback-log에 의도·해석·보완 이유·적용 범위·승인 상태 기록.
3. 사업 사실/접근성/일관성과 충돌하면 그 이유와 대안을 제시. 독립 작업은 계속.
4. 명시적 합의는 context에 반영. 취향 관찰/AI 가설은 제안 표시로 유지. 같은 지적 3회는 검토 신호이지 자동 영구 규칙이 아님.
5. output의 특정 버전에 적용하고 qa 기록과 연결. 시안 개선을 최종 승인으로 오인하지 않음.
6. 이전 기록은 지우지 않고 superseded/반영/보류와 대체 ID를 표시.

중요 선택 질문: 무엇을 결정하는가→실제 대안 2~3개→1순위와 근거→단점/리스크→사용자 판단. 사소한 간격/반복 작업까지 승인 질문하지 않음.
