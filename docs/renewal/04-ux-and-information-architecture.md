# 04. UX·정보구조 조사 브리프
상태: DISCOVERY — 사이트맵, 화면 구조 모두 미확정.

## UX 원칙
- 처음부터 기술 용어를 알아야만 탐색할 수 있게 하지 않는다.
- 그러나 전문 바이어에게는 혼용률·조직·중량·폭·가공 상태·공급조건을 명확하게 제공한다.
- 제품탐색(가장 중요)과 샘플상담(조건부 기회)을 서로 혼동시키지 않는다.
- 어디서든 회사 소개보다 실제 공급 가능 품목과 문의 행동으로 빨리 접근할 수 있어야 한다.
- 비전문가의 문의 문턱을 낮추되 공급 가능 여부를 확정적으로 약속하지 않는다.

## 구매자 여정 가설
A. 전문 소싱 바이어: 검색/광고 → 제품군 → 대표 사양·사용처·공급 상태 → 문의(제품코드 자동 포함).
B. 제품 개발 담당자: 용도/샘플 사진 → '기존 제품과 매칭 가능한지' 안내 → 예상 물량 → 샘플 상담.
C. 신뢰 검증 담당자: 생산/공급 체계 → 직접 편직 근거·공장·협력사 후가공 → 제품 → 연락처.

## 사이트맵 후보(승인 전)
- 홈: 주력 원단 우선, 전문 역량 보조, 2가지 CTA.
- 원단 제품: 제품군별 탐색, 용도별 필터(필터 가능한 실제 데이터가 있을 때만).
- 제품 상세(고유 URL): 대표 사진, 용도, 혼용률·폭·중량 대표값, 가공·납품 상태, 상담 CTA, 관련 제품/정보.
- 생산·공급 역량: 직접 편직, 외주 후가공 경계, 품질·일정 조율 과정.
- 구매 안내/FAQ: MOQ가 달라지는 이유, 보유 생지/가공지, 샘플 전달, 납기 확인 사항.
- 회사/공장 소개.
- 문의: 기성 제품 구매 vs 샘플/유사품 검토, 필요시 편직 상담 분리.
- 콘텐츠: 거래판단 FAQ·회사 고유 팩트 중심; 블로그 원고 중복 복제 금지.

## 홈페이지 첫 화면 가설
- 핵심 헤드라인 후보: 직접 편직하는 제조 기반으로, 완성 원단까지 (사용자 승인 전).
- 바로 아래: 주요 제품 2~4개 카테고리와 대표 원단 이미지.
- CTA1: 원단 제품 확인 / CTA2: 샘플로 상담.
- '어떤 원단이든 생산' '정밀 복제 보장' 표현 금지.

## 2026-10-17 제품 탐색 계층 검토 (Phase 1 제품 사업 입력, 미승인)
- **제품군 → 실제 검증된 대표 공급 사양**의 2단계 콘텐츠 후보. 우선 판매 제품군은 폴라폴리스·인타록·T/R 싱글·DTY 싱글이며 순위는 미정.
- 제품군 콘텐츠: 쉬운 원단 설명, 실제 확인된 특징/사용처, 보유 완제품·보유 생지 후가공·별도 생산 검토 간 경계.
- 대표 공급 사양: 실제 제품코드·실사·혼용률/원사·중량 단위·폭(원통/가공)·색상/가공 가능 여부·공급 경로 등을 **SKU별 검증**한 것만 표시.
- 홈페이지 기존 모달만으로는 공유·검색·정확한 유입 귀속에 제약이 있을 수 있으므로 고유 URL을 UX·SEO·기술 단계에서 검토. 지금은 사이트맵/구현 결정 아님.
- 현재 Firestore에 이미 등록한 제품이 실제 판매할 대표 SKU인지 모르는 상태라 현재 목록을 그대로 재게시한다는 결정은 없다.
- 모든 제품 사양을 한 번에 준비하도록 운영자에게 요구하지 않고, 검증된 대표 항목부터 점진적으로 늘릴 수 있게 설계.

## 2026-10-17 제품군·사용처·공급 방식의 탐색 구조 제안 (미승인)
- **원단명 우선:** 구매 메뉴에서 폴라폴리스/인타록(양면)/T/R 싱글/DTY 싱글을 우선 소개. 별도 추가 판매 제품으로 보드레를 정식 제품 목록에 유지한다. 4개 집중 제품군 사이 강제 판매 순위는 없다.
- **용도 보조:** '본딩용 원단' 등의 표현은 독립 제품군이 아니라 해당 공정에서 실제 사용 적합성이 확인된 제품으로 이어지는 보조 탐색/콘텐츠. 담요용 등도 실제 공급 이력 근거 사용. 동일 제품을 편직/가공지/본딩용으로 여러 건 중복 상품 등록하지 않는다.
- **공급 형태는 제품 내 정보:** '일부 사양 완제품 선재고 / 기존 생지 후가공 / 신규 편직 조건부' 등 제품별 실제 조건을 표현하며, 주력 구매 메뉴를 원단 공정 상태별로만 나누지 않는다.
- **기존 용어 정리:** '플리스'는 폴라폴리스의 관련 설명·검색어로 활용할 수 있으나 완전한 동의어/전 제품 재고로 취급하지 않는다. 기존 '기술 본딩'은 후속 작업 및 바닥지 사용처로 설명하며 가공본딩 자체 공급 보장 금지.
- **사이트 구성 샘플 (미승인):** 홈 → 원단 제품(주력 4종·추가 보드레) → 제품군 소개/검증된 대표 사양 → 공급 조건 확인·문의. 보조 진입: 실제 적용 확인된 용도 안내 → 관련 원단. 제조 및 가공 역량은 별도 설명.
- **아직 미결:** 보드레 카드의 정확한 배치와 노출 강조, 실제 사양·이미지·용도, 메뉴 라벨/URL/CTA 디자인, 5개 제품군 공개 준비 수준. Phase 2에서 승인한다.

## 제품 상세 정보 공개 수준
- 1차: 어떤 용도에 쓰는 원단인지, 실제 사진, 대표 사양, 공급 형태, 문의.
- 2차: 상세 중량·폭·원사/조직·옵션 및 공정별 조건.
- 내부: 세팅값·원가·LOT·고객별 가격/재고 등 비공개.
- 대표 사양과 상시 공급 가능 재고는 다르므로 구분 표시.

## 문의 UX 가설
- Tally 연속성 유지 우선; 제품 상세 CTA가 상품 식별자를 전달할 수 있는지 기술 검증.
- 경로 1: 제품코드/구매 목적/예상 수량/상담 연락처.
- 경로 2: 사진/실물 샘플·용도/희망 사양/반복 수요 가능성/연락처.
- 용어를 모르면 '미정' 선택.
- 개인정보 최소수집, 업로드 보관정책, 수신/회신 동의 확인.
- 폼 제출 성공 이벤트는 실제 성공 시점만 발화.

## 홈페이지 문의 UX와 ERP의 역할 분리 (2026-10-16 D-026, 구체 화면 미승인)
- **확정:** 별도 CRM/외부 관리 프로그램을 만들지 않으며, 실제 발주 시 기존 ERP 거래처 등록·작업의뢰서·원단 송장을 사용한다. 온라인 영업문의 상태 확인용 화면은 ERP에 추가하는 방향.
- 홈페이지·블로그·톡톡·카카오 상담은 고객 접점이며, 내부의 진행 상태·구매 전환 관리는 **ERP 내부 페이지**에 모아보는 구조를 후보로 둔다.
- 문의가 접수됐다는 이유만으로 ERP 거래처/작업의뢰서/송장을 미리 만드는 UX 금지. 신규 문의는 주문/재고에 영향 없는 가벼운 상담 항목으로 유지하고, 거래 진행 시 기존 ERP 참조를 연결한다.
- **사용 편의 후보(미승인):** 사용자가 세부 폼을 매번 장시간 입력하지 않고 유입 경로·관심 품목·짧은 상태만 확인하면 되도록 한다. 기존 이메일·톡톡·카카오 대화 전체를 복사하게 만들지 않는다.
- ERP 화면·상태·보드 구성, 신규 문의 자동 수집 여부, 미발주 업체의 임시 식별 정보, 거래처 중복 방지 UX, 상세 개인정보/권한 정책은 ERP 설계·검증 후 결정.
- 홈페이지 문의 폼과 ERP 사용자 인터페이스는 독립된 시스템이므로 상담 화면의 변경이 ERP 거래 로직에 영향을 주지 않도록 데이터·권한 경계를 설계한다.

## 2026-10-17 문의 메모 MVP 선택 (D-028, 세부 화면 미승인)
- **초기 범위:** 기존 ERP 안에서 의미 있다고 판단한 문의를 짧게 추가/조회/수정할 수 있는 기록 공간을 둔다. 모든 문의의 목록화·관리 강제하지 않는다.
- **운영 방식:** 홈페이지 이메일·블로그·톡톡·카카오(일반 1:1 채팅)·전화 상담은 원래 채널에서 계속한다. 선택한 문의만 업체 식별명/접수 채널/관심 원단/간단한 내용을 직접 메모할 수 있도록 최소 입력을 검토.
- **이후 검토:** 문의량 증가 또는 놓친 상담이 잦아질 때 상태관리, 알림, 자동 수집·중복 감지, ERP 실발주 연결 강화 등을 단계적으로 평가한다. 현재 모두 초기 기능 범위 밖.
- **안전:** 문의 메모 등록 시 ERP 거래처·작업의뢰서·송장/생산/재고/청구 로직에 변경을 일으키지 않는다. 기능 실제 구현은 ERP 코드 및 권한 확인 후 별도 승인.

## 검증
- PC/모바일 2가지 사용자 과제: '폴라폴리스 제품 사양을 확인하고 문의' / '샘플은 있으나 용어를 모르는 고객이 문의'.
- 첫 제품 발견 시간, 필요한 정보 접근, 문의 완료 여부, 혼동되는 항목 검토.
- 실제 제품 사진/스펙이 준비되지 않았는데 와이어프레임을 확정하지 않는다.
