# 06. SEO·AI 검색·콘텐츠·분석 설계 브리프
상태: 연구/후보. 실제 구현·이벤트 반영은 미실행.

## 검색/콘텐츠 목표
- 키워드 반복보다 실제 B2B 구매자가 묻는 질문에 대해 확실한 제품·공급 정보.
- 네이버 블로그: 원단 비교·구매 판단·제조 경험 등 정보 검색.
- 홈페이지: 화성섬유의 제품·실제 가능한 사양/공급 상태·회사 팩트·문의.
- 동일 블로그 글을 홈페이지 컬럼으로 복제하지 않는다.
- AI 검색 최적화는 검색 가능한 명료한 본문, 출처·고유 회사 사실·정보 일관성·갱신에 초점. 인용 보장 주장 금지.

## 제품명/용도/공급 방식 명칭 전략 (2026-10-17 분류 초안, 미승인)
- 구매 메뉴의 실물 제품군: 폴라폴리스, 인타록(양면), T/R 싱글, DTY 싱글 4개 집중군과 추가 판로 보드레.
- 기존 웹 '플리스'는 포괄 검색어로 유지 가능하되 제품의 구체 명칭은 폴라폴리스 등 실제 제조·취급 제품 사양과 연결. '기술 본딩'은 모호하므로 실제 납품되는 본딩용 바닥지 사용처 콘텐츠로 검증 후 연결.
- 제품명 키워드와 '본딩용 바닥지 / 누빔용 / PU코팅용 / 담요용' 같은 **용도 의도 검색**은 구분. 실제 적합 SKU가 입증된 용도만 공개; 모든 제품에 모든 용도 태그 부착 금지.
- '편직/생지/가공지'는 공급 공정·상태를 설명하는 정보이며 구매자가 찾는 개별 제품군과 동일 계층으로 중복 구성하지 않는 방향 제안.
- 검색량이나 AI 노출을 이유로 실제 취급하지 않거나 외주 대응 미확인 원단을 제품으로 만들어서는 안 됨. 페이지 URL/제목/대표 사양은 Phase 2 이후 확정.

## 기술 SEO 필수 요구
- 각 주력 제품에 안정된 고유 URL, title/meta description, canonical, OG 등.
- 실제 텍스트와 검색 가능 구조(렌더링 포함). JS 상태 변경만으로 유일 경로를 숨기지 않는다.
- sitemap.xml, robots.txt, 잘못된 URL 처리, 구조화 데이터는 적용 자격 확인 후.
- 기존 URL 영향과 Search Console 성과를 대조하여 필요할 때만 301·기존 색인 보호 계획.
- 번역 영문 페이지의 독립 URL/언어 태그는 실제 콘텐츠 범위 확인 후 결정.
- 현재 index.html의 og:url이 hwoasung.vercel.app 주소로 설정된 점은 운영 배포/대표 도메인 확인 후 교정 후보.
- 회사 팩트 검증 전 '0% 결함률' '즉시 모든 샘플 대응' '무조건 빠른 납기' 같은 문구를 확정하지 않는다.

## 제품 콘텐츠 템플릿(초안)
제품명/용도/제품코드/실제 이미지/혼용률/대표 중량·폭/조직 또는 특징/생지·가공지 구분/가공 가능 조건/대표 사용처/문의 전 준비자료/관련 원단/관련 구매 가이드/최종 갱신일.
실제 품목별 해당 데이터가 없으면 임의로 만들어 채우지 않는다.

## 유입 구분 및 광고
- 자연 검색/네이버 파워링크/직접/플레이스/블로그/AI 어시스턴트의 단일 지표 합산 금지.
- 네이버 광고 기존 소재의 추적 URL에는 UTM이 없었음. 새 소재에 utm_source=naver, utm_medium=cpc, utm_campaign=powerlink 주소를 설정, 브라우저 접속 테스트 및 광고 심사 '운영 가능' 확인.
- 신규 소재 성과와 기존 소재 성과는 따로 기록. GA4에 실제 paid 세션이 쌓이는지 1~2일 이상 확인 후 추적 완료 판정.
- 직접 방문/referral/organic 분류가 섞일 수 있으므로 과거 지표 역산하여 광고 효과 단정하지 않는다.

## 2026-10-14 실제 데이터 재조회 — 온라인 타깃 진단 근거
**자료:** 연결 GSC Wizard의 `sc-domain:hwoasung.com`, 연결 GA4 `hwoasung-b20ff`. 검색어·유입 경로 확인은 2026-07-15~2026-10-11을 대상으로 조회했고 GSC 기본 최근 90일 개요도 확인. GSC의 최신 확정 시점은 2026-10-11. GA4 시계열은 한국 시간 기준이며 GSC 날짜/집계와 직접 일치시키면 안 된다. **공개 저장소에는 원시/세부 비공개 측정 수치 저장 금지.**

### 관찰 사실
- Google 유입 검색어 표본에서 '편직', '섬유공장', '원단공장' 등 일반 공장/업종 탐색 검색어가 확인된다. 주력 4종의 개별 제품 구매 검색어 유입이 확인된다고 단정할 근거는 이 조회 결과에 부족하다. 다만 **Search Console 검색어 행에는 익명화/제한이 있어 '제품 검색 수요 0' 결론도 불가**하다.
- GSC에서 검색 클릭이 기록된 URL은 거의 홈페이지 루트 경로에 집중됐고, GA4 랜딩 페이지도 '/'에 치중한다. 독립된 원단 상세 URL을 가진 정보 구조의 필요성을 검증해야 한다.
- GA4에는 기본 page_view/session_start/user_engagement/first_visit만 확인됐으며, 이 조회에서는 제품별 탐색과 성공한 문의를 구분할 수 있는 이벤트 및 주요 전환값을 확인하지 못했다. **전환값 0 = 실제 문의 0 아님.**
- 방문 출처에는 Google 자연 검색·네이버 자연 검색·네이버 모바일 검색 관련 referral·직접 유입·광고 검색 도메인 referral·네이버 블로그·AI 어시스턴트 등 여러 경로가 있다. 일부 네이버 광고 관련 도메인은 referral로 보고되어 있어 이를 정확한 유료 캠페인 성과로 계산하면 안 된다. 새 UTM 소재의 실제 `naver / cpc` 기록 검증이 필요하다.
- 특정 온라인 채널이나 구매자 업종이 실제 발주로 이어진다는 근거는 현재 조회된 GSC/GA4만으로 없다. 사용자가 확인한 기존 거래처의 소개·인맥·직접영업 구조와 **온라인 유입 가능성을 별도로 검증**한다.

### 실제 문의 내용과 교차 해석
- 사업용 Gmail의 홈페이지 Tally 접수 알림 표본은 스판·기능성 의류용 원사, 샘플 개발, 특수 생지·직물, 소량 완제품 등 원단 공급 범위가 다양한 문의를 포함한다(식별 정보는 02 문서의 범주 수준만).
- '문의가 존재한다'와 '화성섬유가 반복 공급할 수 있는 주력 제품의 적합한 구매자다'를 구분해야 한다.
- **가설:** 제품명/사양/가공 상태 및 공급 제한을 명확하게 제공하고 구매 목적별 문의 경로를 구분하면, 전체 문의 대비 실제 대응 가능한 비율이 개선될 수 있다. 현재 데이터로 개선 폭을 추정하지 않는다.

### 계측 우선순위 후보 (미승인)
1. **제품별 고유 URL과 page_view:** 4대 주력 제품을 독립 페이지에서 식별 가능하게 하는 URL·측정 계획 (기술 구조 결정 및 실 데이터 준비 전 개발 확정 금지).
2. **문의 행동 이벤트:** 제품 탐색, 연락 수단 클릭, 샘플 문의 시작, 성공한 폼 접수 구분. 전송 성공 여부 확인 전 '문의 전환'으로 계상하지 않음.
3. **유입 출처 정리:** 네이버 광고 UTM의 실제 기록 확인, 소개·직접 영업 고객은 문의 시 직접 유입 경로를 질문하여 구분. Direct만으로 오프라인 소개 여부 추정 금지.
4. **유효 문의 분류:** 자체 편직·재고·원사·가공·MOQ에 실제 맞는지 사후 수동 판정. 단순 폼 제출과 별도로 추적.
5. **성공 지표:** 유효 신규 문의, 적합 문의→견적→실거래 전환, 반복 거래 발생. 초기에 월 목표 수치와 전환율을 임의로 설정하지 말고 계측 정상화 후 기준선을 쌓는다.

## 2026-10-14 사용자 합의된 영업 지표 방향 (D-023)
- **1차 핵심 영업 성과: A 직접 공급형 유효 문의.** 보유 완제품 또는 보유 생지 공급 조건에 맞는 실제 원단 구매 문의를 별도로 추적한다.
- **성장 기회 지표: B 조건부 신규 샘플·사양 개발 문의.** 설비·원사·샘플비·일정 검토가 필요한 경우 A와 구분해서 관리하며 A+B를 하나의 실구매 문의 지표로 합산하지 않는다.
- 단순 홈페이지 문의 폼 제출·전화 클릭은 유효 구매 문의/실발주 성사와 다르다. 내부 적합성 판단 및 견적·발주 확인 뒤 분류한다.
- C 범위 밖/D 추가 확인 필요의 실제 대응 절차, 세부 GA4 이벤트 설계, KPI 수치 목표는 아직 미승인.
- 공개 GA4 이벤트에 고객 개인정보·문의 원문·원가/견적 상세 정보를 전송하지 않는다.

## 거래 규모·반복성에 대한 사업 기준 (D-024, 2026-10-16 문서 동기화)
- **대량 구매형과 반복 구매형은 둘 다 사업적으로 중요한 고객이다.** 대량 주문은 직접 제조에 따른 생산 효율과 유연한 단가 검토의 여지가 있고, 반복 구매는 공장 회전율 및 공급 안정성에 기여한다.
- **A 직접 공급/B 조건부 개발은 '공급/문의 유형'**, 대량/반복은 '거래 가치'로 서로 독립적으로 분류한다.
- 높은 세팅·원사·가공 부담과 소량·일회성이 겹치는 문의나 샘플 이후 실질 진전이 없는 문의는 상담 투입 대비 가치가 낮을 수 있다. 자동 불합격/일률적 소량 거절과는 구분한다.
- **추적 제안(미승인):** A형 실발주와 B형 개발 진행을 분리하고, 거래 성사 후에는 대량 첫 발주와 재발주 여부를 추가 확인한다. GA4 이벤트만으로 구매 규모/재구매를 판정할 수 없으므로 영업 업무·ERP 기록과 연결하는 최소 절차는 후속 확인.
- 주문별 금액·원가·사양 등 비공개 영업 데이터는 공개 GitHub나 GA4에 저장하지 않는다.

## 2026-10-16 문의 후속 추적 현황 (D-025)
- **현황:** 홈페이지 전용 폼의 이메일 접수 알림만 누적되며, 블로그·톡톡·카카오비즈니스는 각 채팅 이력만 남는다. 실거래 여부·샘플/견적 진행 상태를 통합 관리하는 목록은 없음.
- **데이터 한계:** GA4에서 방문/클릭/문의 성공을 측정하더라도 그 자체만으로 실발주 또는 반복 구매가 되었는지 판단할 수 없다. 별도 최소 영업 기록 및 후속 대조 방법이 필요.
- **MVP 운영 대안(미승인):** 유입 채널/문의 대상 원단/문의 적합 분류(A 직접 공급, B 조건부 개발, C 부적합, D 보류)/진행 상태/발주 성사/재발주 여부만 건별로 추적. 소스 이메일·대화 이력은 기존 시스템에 두고 중복 기록은 줄임.
- **D-026 확정에 따른 수정:** 별도 표·독립 관리 앱은 선택지에서 제외, **ERP 안의 온라인 영업문의 페이지**로 관리. 미결은 개인정보 권한/저장 주체, 최초 등록 수동·자동 가능성, ERP 거래처·작업의뢰서·송장 매칭 기준. 현재 시스템에 자동 수집 기능이 있다고 주장하거나 코드를 구현하지 않는다.
- **보안:** 고객명·연락처·대화 원문·개별 주문 금액 등은 공개 GitHub 및 GA4의 이벤트 속성에 포함하지 않는다.

## 2026-10-16 ERP 중심의 영업 성과 확인 원칙 (D-026)
- **사용자 확정:** 별도 CRM이나 영업관리 프로그램을 사용하지 않고, ERP에 영업문의 관리 페이지를 추가한다. 신규 거래 성사 시 이미 작성하는 ERP 거래처 마스터·작업의뢰서·원단 송장을 성과 판정의 근거로 활용한다.
- **웹 측정의 역할:** 검색/광고·홈페이지 방문·문의 행동 등의 선행 지표. Tally·톡톡·카카오 문의는 실제 유입 경로를 보존해야 한다.
- **ERP 측정의 역할:** A/B 적합 문의의 영업 진행 및 기존 ERP 거래 데이터에 근거한 실제 발주·재발주 성과 확인. 문의 한 건이 자동으로 발주 확정이 되는 것으로 간주하지 않음.
- **연결 요건 후보:** 초기 문의 ID → 거래처 ID → 관련 작업의뢰서/송장(여러 건 허용) 참조. 신규 문의만으로 거래처·작업의뢰서·송장을 강제 생성하거나 실제 생산/재고/청구 데이터 변경 금지.
- **유입 경로와 발주 연결을 위한 최소 기록:** 최초 유입 채널, 문의 발생일, 관심 제품/용도, 현재 단계, 실제 업체 연결 여부. 실물 샘플 원문/거래 금액 등 민감 정보는 ERP 권한 정책에 따르고 공개 GitHub/GA4에 업로드 금지.
- **구현 전 검증(미승인):** 실제 ERP의 거래처 ID 및 송장·작지 데이터 관계, 중복업체 매칭, 과거 거래처에 대한 유입 경로 소급 처리, 담당자 승인/권한, 홈페이지 폼 입력을 ERP로 전달하는 합법적·안전한 방식, 톡톡·카카오 자동 수집 제공 여부.
- **정책:** ERP 기록이 실제 발주 성사를 확인하는 주 근거이며, GA4의 주요 이벤트 수와 ERP의 영업 실적은 동일 지표가 아니다. 별도 ERP 구현은 추후 ERP 프로젝트에서 설계·승인한다.

## 2026-10-17 ERP 문의 기록 최소화 결정 (D-028)
- 카카오비즈니스는 기본 1:1 채팅을 사용함. 당장은 **의미 있다고 판단한 문의만 ERP 내부에 짧게 수동 메모하는 방식**으로 유지하며, 자동 수집 대기함·후속 영업 단계 의무 기록·알림·CRM 통합·송장 자동매칭 등은 **현재 구현 범위에서 제외**.
- A 직접 공급형 우선/B 조건부 개발형 별도 성장 기회라는 **사업 목표(D-023)** 자체는 유효하나, 현재 모든 문의나 단계별 전환을 수집하는 것이 실무 의무이거나 구현 승인이라는 뜻은 아니다.
- 현재 선정된 문의만 기록하므로 **전체 문의 적합률·전체 문의→실발주 전환율을 신뢰할 만하게 계산할 수 없다**. 해당 통계는 후속 수집 범위 확대/측정의 완전성 확보 뒤 도입한다.
- 네이버/Google 검색의 검색어·페이지 유입 기본 지표 및 새 홈페이지의 방문 행동 계측 설계는 별도로 검토 가능하나 ERP의 CRM 고도화와 연계해 반드시 동시에 개발할 필요 없다.
