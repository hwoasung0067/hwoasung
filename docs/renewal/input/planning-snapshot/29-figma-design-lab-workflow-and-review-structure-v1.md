# 화성섬유 홈페이지 리뉴얼 — Figma 디자인 랩 운영·시안 축적 설계 v1
작성: 2026-10-23 KST
상태: **사용자 '나중에 시안 뽑을 때 연결된 Figma에 시안 쌓고 싶다'는 작업 방식 수락 및 구현 전 운영 설계. Figma 파일/노드/이미지/프로토타입 생성은 아직 하지 않음.**
연결: D-041 기획·설계 먼저 합의 후 화면 제작, D-043 비언어적 브랜드 경험, D-044 브랜드 정체성, D-045 별도 의견 결정 불필요할 때 자율 진행, D-046 A형 짧은 선언 히어로 방식, D-047 실제 미디어/현재 홈페이지 감사, 25~28 상세 디자인 기획.
관련 공식 외부 레퍼런스: https://arville.com/ (공정 실체·제품/사용 산업/제조 역량 탐색·후반 신뢰), https://www.tintextextiles.com/ (간결한 브랜드 인상·응용분야·별도 Showroom·Innovation·News). 공식 사이트 텍스트 구조는 확인, 특정 hover·pointer 애니메이션 프레임/성능은 후속 실제 시각 관찰 전 정확히 복제한다고 주장 금지.

## 1. 지금 바로 Figma 파일을 만들지 않는 이유
- 사용자는 **'기획·전체 섹션·콘텐츠·디자인 방향을 먼저 결정한 뒤 시안/구현'** 하라고 분명히 지시함(D-041); 신규 v1/v2 실패를 반복하면 안 됨.
- 이번 발언의 '나중에 ... Figma를 이용해서 시안들을 쌓고 싶다'는 **디자인 시안 생산 시 사용할 작업 공간 선호**. 지금 디자인 파일을 만들고 그 안에 미승인 웹 페이지를 건설하라는 요청은 아님.
- A형 한 문장 히어로라는 **표현 전략만 승인**, 정확한 브랜드 카피·R1/R2 사진/레이아웃·메인 6섹션 순서/합치기·실사 품질은 사용자 최종 선택 전.
- Figma는 **실제 시안과 승인·차이·수정 기록**을 검토하는 편집형 공간. **사실·운영정책·결정 로그의 정본은 GitHub** `docs/renewal` 상태/decisions. 승인 후 Codex 구현 대상도 GitHub 설계 승인판으로 명료하게 넘김.

## 2. Figma 연결 가용성 확인(2026-10-23)
- 연결된 Figma 도구의 `whoami` 읽기 전용 질의 성공, **한 개 팀 계획에서 Full 편집권한**을 가진 연결 사용자 확인(계정 식별값은 공개 GitHub에 보존하지 않음).
- 향후 Figma Design 파일 생성을 지원하는 `create_new_file`, 파일 편집을 지원하는 `use_figma` 도구가 연결됨. 실제 디자인 파일은 **아직 생성하지 않음**, Figma 파일 URL/키도 아직 없음.
- 파일 생성 직전 공식 skill `figma-create-new-file`, `figma-use`; 화면 작성 시 `figma-generate-design` 지침을 다시 확인 후 사용. `whoami` 결과에서 하나의 팀만 확인됐으므로 추후 파일 생성 시 팀 선택 질문 없이 권한 재확인 후 진행 가능(계정 변화 시 갱신).
- **중요:** 외부 이미지·영상이 바로 Figma에 임의 연결되거나 모든 효과가 실제 웹사이트처럼 재생된다고 가정 금지. Figma의 편집 가능한 프레임·텍스트·컴포넌트와 클릭/hover 프로토타입을 우선, 복잡한 웹 애니메이션은 **모션 스토리보드 + 작동 정의**로 설명하고 실제 구현 검증은 별도.

## 3. 추천 워크스페이스 (디자인 제작 개시 승인 뒤)
### 파일 이름
`HWOASUNG | Website Renewal | Design Lab` — **파일 한 개에 모든 히어로 방향·PC/모바일·수정·승인/보관을 누적**. 출시 후 확장/보존 정책은 관리 비용을 검토해 결정.

| `01_REFERENCES · Visual Language` | Arville/Tintex에서 어떤 시각 원리를 가져오는가 | 회사별 분위기/사진/타이포/스크롤 리듬·인터랙션 분석 메모, **원본 사이트 링크·출처 표시**. 이미지를 실제 자사 사진처럼 쓰지 않음 |

## 4. 프레임/버전 네이밍 규칙
예시:
- `EXP-001 | HERO | R2 editorial | Desktop 1440 | DRAFT`
- `EXP-001 | HERO | R2 editorial | Mobile 390 | DRAFT`
- `EXP-002 | HERO | R1 real factory | Desktop 1440 | DRAFT`
- `REV-001 | HOME | visual-led | Desktop 1440 | FOR REVIEW`
- `REV-001 | HOME | visual-led | Mobile 390 | FOR REVIEW`
- `APP-001 | HOME | Desktop+Mobile | APPROVED` — **사용자 승인 후에만 붙임**.
- `ARCH-001 | HOME | rejected prototype | REFERENCE ONLY`.
**원칙:** 같은 파일에 새 프레임/섹션을 늘려 **비교 가능한 과거 시안 보존**. 확정 시안과 실험을 섞어놓고 '최종'처럼 보이게 하지 않음. GitHub의 design-decision-log에 해당 Figma URL·프레임 ID·승인 날짜/사유 기록.

## 5. 실제 디자인을 쌓는 순서 (향후)
**Gate A — 기획 정렬:** 브랜드 철학/메인 섹션 목적·순서/실물 자산(기존 GIF·제품 5종 사진·실제 편직 현장)을 확인. 현재 23·25~28이 초안. 승인 필요한 항목은 A1/A2 히어로 문구·R1/R2 사진/레이아웃 노선·04 사용처 독립/통합.
**Gate B — Mood & Reference:** Figma `00/01`에 정확한 설명과 레퍼런스 시각 비교판 배치. 디자인 원리 3~5개(여백·이미지 구성·타이포 리듬·사용자 포인터/스크롤 효과의 이유)를 실제 채택/비채택으로 문서화.
**Gate C — Hero direction:** PC/모바일에서 **같은 콘텐츠·같은 실제 자사 이미지**로 R1/R2 또는 동등한 두 방향을 비교. 문구/사진/레이아웃을 한꺼번에 다른 것으로 바꿔 무엇이 좋은지 판별할 수 없는 시안 비교 금지.
**Gate D — Connected scroll scenes:** 02 실물 원단→03 실제 편직 근거→(04 쓰임 자료 확보 시)→05 실무 인사이트→06 자연스러운 마무리를 **하나의 스크롤 경험**으로 편집. 2열/3열 기계적 카드 반복 금지, 콘텐츠 없는 예쁜 목업 금지.
**Gate E — Responsive & Interactions:** PC·모바일 배치, 제품 진입, 마우스 hover/터치 대체, prefers-reduced-motion, 키보드/텍스트 가시성. Figma Prototype는 보여줄 수 있는 범위만 재현; 구현 전 복잡한 모션은 스토리보드로 설명.
**Gate F — Review:** Figma에서 의견 수렴·바로 수정·버전 축적, 승인안 `APP-`로 분리 → GitHub 최종 설계 상태 동기화 → Codex 구현 프롬프트. **디자인 파일 생성이나 승인 자체가 운영 사이트 배포 권한을 부여하지 않음**.

## 6. 디자인 리뷰에서 반드시 나란히 비교할 항목
1. 히어로의 3초 인상: **정말 화성섬유 브랜드로 느껴지는가?** (다른 제조사 이름으로 교체해도 동일하면 재설계)
2. 타이포와 사진 비중: 문구가 공정/원단 주제를 가리고 있지 않은가? 한국어 한줄은 쉽게 읽히나?
3. 비언어적 신뢰: 실제 환편기·원단·공급 근거로 전문성 느껴지는가, **자기자랑 문구 반복** 아닌가?
4. 가까운 소통: 사용자가 찾는 원단/용도/상담 진입이 편하고 부담스럽지 않은가?
5. 리듬/완성도: 첫 Hero에서 제품·제조·인사이트까지 **스크롤할 이유가 생기되 강제하지 않나**?
6. 핸드폰: 핵심 이미지가 크롭으로 사라지지 않고 원단 이름/CTA가 숨지 않나?
7. 실제성: 고객 후기·결함 0·정량 납기 20%·무조건 주문 제작·협력 후가공을 자체라고 묘사하는 장면 전부 금지.
8. Figma 레이어가 **편집 가능한 텍스트·컴포넌트·이미지 구조**인가? 전체 스크린샷을 한 장으로 붙여놓은 가짜 Figma 디자인이면 불합격.
9. 영상이 없더라도 디자인이 완성되는가? 비디오 파일·제품 실사를 아직 확보하지 못했으면 사실 확인 상태 표시.
10. 메인 이탈 관찰을 후속 검증할 수 있게 첫 제품 클릭·상담 진입·스크롤/CTA 등을 구분할 수 있나(공개 이벤트에 개인정보/고객 사양 기록 금지).

## 7. Github와 Figma 역할 분담
| GitHub | Figma |
|---|---|
| 브랜드 진짜 회사 사실/업무 제약의 **정본** | 보기에 좋고 실제 수정 가능한 시각 시안 |
| 정책·디자인 요구/컴포넌트 사양의 글 문서 | PC·모바일 레이아웃, 모션 프로토타입/스토리보드 |
| 승인/반려 결정 로그 `decisions.md`, `project-state.md` | 개별 EXP/REV/APP 시안 프레임과 코멘트 |
| Codex 구현 작업범위/회귀테스트 | 구현에 전달할 화면·토큰·컴포넌트 트리 |
- 디자인 수정 이력은 Figma에서 보이게, 승인 내용은 GitHub에도 기록하여 **채팅·Figma·코드 사이에서 어느 게 최신인지 혼선 방지**.
- 사용자에게 Figma 링크를 전달할 때 해당 화면 프레임을 정확히 지정. 자료 제작/검토 단계에서 혼자 '사용자 승인' 표시 금지.

## 8. 현재 완료/다음
- ✅ 연결된 Figma 팀 1개·Full seat 등 도구 가용성 **읽기 전용 확인**.
- ✅ 향후 Figma 파일명/페이지/프레임·버전·승인 관리 규칙과 실제 시안 작성 게이트 기획.
- ✅ 기존 레퍼런스 공식 홈 텍스트 구조 재확인(Arville: Hero→Products/Sectors/Capabilities→Why→Partners, Tintex: Hero→시장분야→Innovation→Insights).
- ⏳ **Figma Design 파일은 아직 안 만들었다.** 사용자가 언급한 '나중에 시안 제작 단계'로 이동한 시점에 생성한다.
- ⏳ 히어로 최종 한글 카피/실제 자사 대표 사진/PC·모바일 방향 선택·메인 섹션 배치/사용처 분리 판단 필요. D-041대로 설계 합의 전 시안 생성 금지.
- ➡ 다음 비결정 업무는 자사 이미지의 실제 사용 여부·제품 5종 실사진 자료 공급원과 연결 가능한지를 검증하고 섹션 02/03에 쓸 콘텐츠 우선순위를 정리하는 것. 접근 경로가 없다면 사용자가 원본 공유하는 결정을 할 때 한 번에 요청한다.
