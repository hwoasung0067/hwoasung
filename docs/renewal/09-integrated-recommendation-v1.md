## A. 이 문서의 역할과 승인 방식
- 기존의 '세부 항목 하나씩 질문 → 각 항목별 답변' 흐름 대신 **필수 큰 맥락만 질문하고, 나머지는 책임 있게 통합 추천안을 먼저 작성 → 사용자가 전체 검토·일부 수정·승인**한다.
- 아래에서 **[확정]**은 이미 사업·운영에서 확인한 원칙, **[추천]**은 디렉터 관점의 기본안으로 사용자가 승인/수정할 수 있는 내용, **[검증]**은 실제 코드·자산·데이터나 사용성 테스트 후 결정할 사항.
- 사안이 '실제 공급 가능 품목/MOQ·가공 역량·계약/개인정보·시스템 변경 권한/비용'에 영향을 주는 경우만 추가 확인. 이미 답한 사실은 다시 묻지 않는다.
- 이 문서는 P1~P5를 관통하는 **방향·콘텐츠·화면·기술 가설의 일괄 리뷰용**이다. 최종 구현 명세, 시안, 코드 승인과 혼동하지 않는다.
- 사용자의 승인/수정 내용을 반영하여 각 분야의 상세 설계를 작성하되, **새 인터뷰를 늘리지 않고 초안의 차이/위험만 재검토**한다.

## E. 홈페이지 첫 화면과 스크롤 구성 [추천]
1. **히어로**: 실제 편직 설비/원단 디테일 중심의 사진 또는 절제된 영상 + 명료한 제조/공급 메시지. 큰 제품 카드 4개가 히어로를 모두 차지하지 않아도 된다.
   - 1차 행동 '원단 찾아보기'
   - 2차 행동 '용도·샘플로 상담'
   - 첫 화면에서 원단 직접 편직·공급 회사라는 정체성이 반드시 드러나야 함.
2. **두 가지 탐색 카드**: '원단명을 알고 있어요' / '용도·샘플부터 확인하고 싶어요'. 전문가를 억지로 장황한 상담 폼에 넣지 않음.
3. **실제 취급 원단 제품군**: 4개 주력 + 보드레. 실물 사진 우선, 같은 이미지 중복 사용 금지, 충분한 설명과 제품 페이지로 연결.
4. **어떤 생산·공급을 담당하는지**: 편직 설비·생지, 일부 사양 완제품 선재고, 협력 가공, 가능성 검토. 모든 규격 재고/전 공정 자가공장 주장 금지.
5. **사용처별 실제 사례**: 본딩 바닥지·누빔(예: 보드레)·담요 등의 용도를 실제 적용된 제품과 연결, 미확인 용도는 무리하게 확장하지 않음.
6. **구매 전 안내 + 상담 CTA**: 완제품 재고·생지 후가공·새 생산/샘플 검토의 차이, 요청 시 필요한 정보, 연락/폼 경로.
7. **회사 신뢰·연락처·푸터**: 공장/회사 정보, 응대 채널, 기존 블로그 연결.
- 섹션 순서·히어로 높이·CTA 디자인은 실제 P2 시안과 모바일 사용성 테스트에서 확정. 위는 출발 권장안.

## F. 제품 페이지·데이터 공개 기준 [추천]
### 제품군 설명 → 검증된 대표 공급 사양
- **제품군 페이지**: 원단 이름/실제 특징/적용 용도/직접 편직과 공급 체계/문의.
- **대표 사양**: 실제 회사의 생산/납품 기준으로 검증된 제품만. 표기할 수 있는 항목: 사진, 제품명/내부 또는 공개 제품 코드, 혼용 또는 원사, 조직, 중량(단위 명시), 폭(원통폭·가공폭 구분), 적용 가능한 가공, 색상 예시, 공급 형태.
- **제조 상의 적용과 공급 보장 분리**: '활용 사례'는 모든 바이어 사양에서 똑같이 구현된다는 뜻이 아님.
- **노출하지 않을 기본값**: 고객별 단가/원가/LOT/실시간 창고 수량/배정 물량/기계 세팅 비밀. 검증되지 않은 '항상 재고 있음/당일 출고/500yd 신규생산' 문구.
- **원단 상태**: 재고 완제품 일부 규격, 보유 생지 후가공 상담, 신규 편직 검토를 구분하고 개인별 물량·납기는 별도 확인.
- **진행 방식**: Firestore 현재 등록 상품을 자동으로 판매 가능 SKU라고 인정하지 않는다. 기존 관리자 DB/ERP/실물 샘플·기존 납품 사양 중 실제 확인 가능한 항목부터 점진 공개.

## G. 상담 경험 [추천]
- 제품 페이지에서 문의하면 해당 원단 정보를 미리 전달할 수 있는지 기존 Tally 기능·보안/기술 검증.
- 용도·샘플 기반 문의는 전문 명칭이나 중량을 몰라도 진행 가능. 필요 항목: 제품 용도, 사진/실물 샘플 여부, 희망 수량·가공 상태·일정, 연락처. 모르는 정보는 '미정' 허용.
- **중요 원칙**: 샘플 상담은 동일 제품 복제·무료 개발·무조건 MOQ 수락 약속이 아니다. 신규 원사·기계 세팅 비용/작업 가능 시간은 실제 사업 원칙 적용(D-016~D-019).
- 현재 운영 중인 네이버 톡톡·카카오 1:1·전화·메일 접점은 유지. 채널 자동 통합 CRM은 초기 범위 아님.
- ERP 내 '선택적 중요 문의 메모'만 단순 기록하는 D-028 방향을 유지. 홈페이지 문의 폼 자동 ERP 유입을 필수화하지 않음.

## H. 디자인 방향 [추천]
- 시각 언어: **현대적 제조 스튜디오/공장** — 실물 원단 표면, 니트 조직 클로즈업, 편직 설비·생지 공정, 기술적 상세가 드러나는 그리드·여백·명확한 서체.
- 컬러 가설: 차분한 차콜/미색/중립 회색 바탕에 기술적 강조색 소량. **구체 색상과 브랜드 토큰은 P3에서 비교 승인**; 이 팔레트를 확정이라고 쓰지 않는다.
- 사진 우선순위: 동일 원단 이미지를 각 제품에 재사용 금지; 먼저 실사(질감/스케일/앞뒤/기계·공정), 자료가 없으면 준비 중 상태를 정직하게 처리. 생성 사진을 실제 판매 SKU처럼 보이게 금지.
- 화려한 3D, 과한 움직임, 읽기 어려운 영어·작은 글씨, 인물·나이를 내세우는 브랜드 스토리 지양.
- 이미지 제작/촬영 계획은 최종 색상·화면과 병행해 만들되 **나중에 실사 자산을 일괄 확보할 운영 계획**을 별도로 작성.

## I. SEO·광고·콘텐츠 역할 [추천]
- 홈페이지: 실제 취급 원단 사양·가능한 공급 형태·제조 팩트·문의로 연결되는 기준 정보.
- 네이버 블로그: 편직 원리·원단 차이·실무 체크포인트·구매 설명 등 정보형 콘텐츠. 홈페이지 제품 페이지로 맥락 있는 링크 유도. 그대로 복제하지 않음.
- 네이버 파워링크: 무조건 회사 메인으로 보내기보다 검색 목적에 맞는 원단/용도 랜딩을 조건부 검토. 추적 URL은 실제 GA4 UTM 반영 확인 후 확장.
- 기술 SEO: 원단별 안정적인 URL·검색 가능한 본문·title/description·OG/canonical·sitemap·색인/리디렉션 검증. 네이버/Google AI 검색은 명확하고 사실 기반의 고유 콘텐츠 우선, 인용/상위노출 보장 없음.
- '편직공장' 일반 검색만이 아니라 **제품명·원사/조직명·정확한 사용처 의도**를 함께 다루되, 검색량·전환율이 입증되었다고 단정하지 않음.

## J. 기술·데이터 범위 [추천, 코드 확정 아님]
- 기존 React/Vite/Firebase/Firestore/Cloudinary/Tally 연동을 **가능한 안전하게 활용**하는 전제로 기술 선택 비교. 현 단계에서 무조건 새 프레임워크로 재구축하자는 주장 아님.
- 상품 상세는 상태 전환 모달만으로 끝내지 않고 **직접 접근·공유·색인 가능한 제품별 URL**을 검토. 동적 데이터 렌더링·SEO·성능 대응 방식(프리렌더/SSR 등)은 개발 전 비교.
- 기존 제품 DB, 관리자 업로드, 문의 제출, 인증/보안 규칙을 개발 전에 검증. 임의 제품 데이터 덮어쓰기·원가/거래 정보 노출 금지.
- GA4 기본 유입 및 제품·상담 진입/폼 성공 이벤트만 정확하게 측정. 개인정보/견적 메모는 이벤트로 보내지 않음. 방문/클릭과 유효문의/실발주·재구매는 별개 지표.
- 개발·배포 전 기존 제품 DB·운영 설정·문의 흐름 백업, 프리뷰/테스트, 점진 릴리스·롤백 정의.
- main/운영 홈페이지/ERP는 **이 권장안 승인만으로 수정하지 않는다**.

## K. 권장 범위/우선순위
### 1차 리뉴얼 필수
- 명확한 브랜드 첫인상, 제품명/용도 두 접근 경로, 취급 4종+보드레 제품 소개, 실제 편직 기반 신뢰, 제품 정보/공급 조건, 편한 문의, PC·모바일 사용성.
- 제품별 URL 및 최소 검색/계측 기반, 기존 문의·관리자 기능을 망가뜨리지 않는 기술 구조.
### 후속 강화
- 실제 제품별 수많은 SKU/스펙 채우기, 용도별 개별 상세 페이지 확대, 영문 수출 타깃/보드레 해외 SEO, 고급 제품 필터, 상담 자동 분류/ERP 자동 연결, 전환율 정밀 측정.
- 후속 강화는 1차 출시에 필요한 실측 정보가 없으면 억지로 끼워 넣지 않음.

## L. 승인 전 반드시 확인할 사실
1. 기존 홈페이지 운영 배포가 어떤 커밋/호스팅/도메인을 실제로 사용하는지, 기존 제품 DB/이미지·관리자·문의가 온전히 유지되는지.
2. 공개 대표 SKU에 대한 실제 사양·실사 확보 가능성과 해당 용도 연결의 적합성. 준비된 항목부터 공개하도록 범위 조정.
3. Tally 개인정보 동의·보관 및 폼 성공 판정, GA4 이벤트/유입 측정 정상화.
4. 리뉴얼 규모/기술 제약이 기존 코드 개선만으로 충분한지, 더 큰 재구축이 필요한지. 코드를 읽고 영향·비용·운영 난이도 비교 후 결정.

## N. 사용자의 검토 방법
- 기본안 전반이 맞으면 '통합안 기본 방향 승인, 세부 설계 진행'이라고 회신하면 됨.
- 특정 부분을 고치고 싶다면 '메인 히어로는 이렇게', '디자인은 저렇게', '제품 공개는 조금 더/덜' 등 **수정할 항목만** 전달. 나머지는 추천안 기준으로 다음 상세 설계에 반영.
- **세부 화면, 실제 문구, 디자인 시안, 데이터·기술 구현의 최종 승인은 후속 단계에 남는다.** 전체 승인=즉시 개발·배포 승인이 아니다.
