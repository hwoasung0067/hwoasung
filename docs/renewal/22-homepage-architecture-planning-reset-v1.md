## 3. 원점 재설계의 가장 중요한 전략
**회사 정보 진열과 고객 문제 해결 강의 사이의 적절한 균형.**
- v1 실패: '공장 소개→제품 소개→문의' 정보를 회사 중심으로 진열.
- v2 실패: 첫 3개 화면을 특정 '본딩용 인타록 문의/사양 확인/공급 경로' **하나의 사용자 시나리오**가 독점. 홈페이지의 격·제조 정체성/실제 주력 제품의 매력·도매바이어 접근성이 약해질 위험. Arville/Tintex의 폭넓은 브랜드 세계와 편집 리듬 미흡.
- 새로운 목표: **브랜드가 왜 거래 고려대상인지 보여주되, 바이어가 어떤 원단을 취급하는지 빠르게 알게 하고, 깊은 기술 설명/상담 결정은 해당 제품·용도 페이지로 내려보낸다.**
- 구매자는 반드시 '문제가 생긴 사람'만이 아님. 신규 오더·추가 공급처·좋은 파트너 탐색·해당 원단 공급 안정성을 위해 방문할 수 있음. 과장된 불안 조성 금지.
- 사용자가 이미 거래하는 공장을 버리게 하려는 목적이 아니라, **특정 사양에 대해 화성섬유를 경쟁력 있는 추가 후보로 상담해 볼 합리적 이유**를 만드는 것이 실무적 성과.
- 원단명/보유 재고·용도/샘플 두 경로 모두 실제 사양·수량·일정에 대한 상담 필수(D-032).

## 5. 섹션 순서에서 결정해야 할 가장 큰 분기 — 별도 질문 여러 개 금지
**A — 제품 즉시 탐색형(비교할 대안):**
Hero → **취급 원단/용도 진입** → Why Hwoasung(가치와 실제 증거) → Manufacturing(실제 편직) → Partner Insight(관계·사례) → 상담.
- 장점: 제품 찾으러 들어온 도매/가공 실무자에게 친절, Tintex의 라이트한 카탈로그/분야별 진입. 설득은 03부터 깊게 쌓음.
- 리스크: 02에서 원단 카드/제품만 보이면 16 v1의 범용 홈페이지처럼 보일 수 있음. Hero와 03의 강한 브랜드 가치 연결·비주얼 필요.

**B — 브랜드 임팩트 우선형(현재 추천 검토안):**
Hero → **Why Hwoasung(핵심 선택 이유와 근거)** → 취급 원단/용도 진입 → Manufacturing → Partner Insight → 상담.
- 장점: 사용자가 D-038에 지적했던 '다른 공장과 무엇이 다르냐'를 첫 스크롤에서 답하며 Arville Why/실제 증거와 어울림. 단, `Why Hwoasung`을 흔한 강점 4개 아이콘으로 전락시키지 않고 **실제 판단/실사/거래 실무의 한 가지 강한 장면**으로 연다.
- 리스크: 빠르게 보유 제품을 확인하려는 실무 구매자의 탐색을 방해할 수 있음. 메뉴/CTA로 빠른 제품 진입이 필수.

**현재의 추천:** B를 우선 논의하되, 첫 화면에 '취급 원단 바로가기'를 뚜렷하게 배치해 A의 즉시 탐색 장점을 살린다. 사용자가 실제 첫인상을 우선했기에 02 첫 스크롤에서 화성섬유의 선택 이유가 느껴지지 않으면 제품 화면을 03에 둔다고 해결되지 않는다. **둘 다** 사이트의 실제 길이·사진과 텍스트의 비율·하위 페이지 경계를 결정하기 전에는 최종안 아님.

## 6. 페이지 전체 정보구조 — 홈에 모두 넣지 않기
- **HOME**: 누군지, 어떤 원단을 다루는지, 왜 거래 고려 대상인지, 실체와 작업 방식, 다음 행동. 메인은 설득/진입 허브.
- **FABRICS**: 폴라폴리스/인타록/DTY 싱글/T/R 싱글/보드레 제품군과 검증 사진·기본 설명·원단 사양 확인 문의(모든 공급 상담 필수). 웹 공개할 상품 SKU/재고/SEO 범위는 다음 단계.
- **APPLICATIONS 또는 USE CASES(검토)**: 본딩 바닥지·누빔·담요·PU코팅·봉제 등 용도 설명, 어떤 사양을 확인해야 하는지, 관련 제품 및 상담. 독립 메뉴스가 실제 자료/수요가 충분한지 검토 후 확정.
- **WHY / MANUFACTURING(정보구조 미정)**: 자사 편직 설비/사람/원사·생지·가공 협력 프로세스, 반복거래의 일하는 방식. 두 페이지 분리는 콘텐츠 양에 따라 검토.
- **KNOWLEDGE / INSIGHTS**: 블로그/실무 지식과 홈페이지의 역할 연결. 블로그 글 통복제 대신 근거가 필요한 곳에 맥락 링크.
- **CONTACT**: 제품명·사양 또는 용도·샘플로 시작하는 공급 가능성 상담.
**메뉴 수/라벨은 미정.** 별도 하위페이지의 SEO/접근성/문의 전환은 후속 작업.

## 7. 각 섹션에서 채워야 할 공통 설계 카드
섹션을 '예쁜 블록'이 아니라 **승인 가능한 설계 단위**로 관리:
1. **방문자/상황**(누가 왜 이 섹션을 보나)
2. **사용자 심리/의문**(구체적 질문 하나)
3. **남길 메시지**(한 문장. 메인 홈 광고 카피와 구분)
4. **보여줄 객관적 증거**(실사 사진/실물 사양/실제 거래·반복 관계)
5. **콘텐츠 구성**(큰 사진·영상 / 제품 그룹 / 고객 사례 / FAQ / 인터랙션: 필요성 검증)
6. **시각적 리듬**(앞/뒤 화면과 밀도·색/이미지/여백이 어떻게 달라지나)
7. **유도 행동**(제품 상세·용도 선택·블로그 근거·문의)
8. **검증 상태/한계**(확인/미확인/사용 금지)
9. **반론**('타사도 똑같은데?', '지금 내 사양 가능해?'에 답하나)
10. **PC/모바일 우선순위**(모바일은 카드 뭉치·강제 클릭 탭 남발 X)
**모든 섹션에 이 카드를 완성/검토한 후에만 UI 시안으로 넘어간다.** 세부 폰트·색상·버튼 인터랙션은 그다음 UX/디자인 단계.

## 8. 제안 단계별 승인 게이트
- **P1 포지셔닝/구매자 설득 기준:** 17~20 참고, 사용자가 핵심 선택 이유/우려의 우선순위 승인 (현재 기초 조사, 일부 가설 미확정).
- **P2 홈/하위 정보구조**(지금부터): 메인에 **어떤 섹션/어떤 순서/섹션 간 연결**을 만들지 큰 그림 합의. 홈·제품군·사용처·제조·지식·문의 역할 구분.
- **P3 섹션 콘텐츠/증거 설계:** 매 섹션 10개 카드 채움, 확보/추가 촬영·검증 필요 자료 분류. 구현 비용 과대화 금지.
- **P4 디자인 디렉션:** 레퍼런스에서 실제 채택할 타이포·여백·사진 비율·색감·스크롤 효과·PC/모바일 위계 **콘셉트 보드** 확정.
- **P5 와이어프레임/시안:** 승인된 구조와 자료 슬롯/영상 보류 상태를 바탕으로 PC+모바일 화면. 전 단계 완료 전에는 디자인 HTML 생성하지 않음.
- **P6 기술/SEO·마케팅·접근성 교차검토 + 최종 명시적 구현 승인**.
- **P7 Codex 구현/실운영 검증**(승인 후).
- 각 단계에서 합의가 필요할 때 **추천안 1개+큰 대안 1개**를 보여주고 편한 피드백을 받는다. 이미 공유된 내용 재질문 X.
