## 가장 중요한 확인 완료 사항 (중복 질문 금지)

| 영역 | 사용자 확인 사실/전략 | 결정 |
|---|---|---|
| 사업 우선 목적 | 편직 임가공 자체의 문의보다 **직접 편직 기반의 원단 공급**, 특히 가공 완료 원단 판매 확대 | D-003~D-005 |
| 주력 4개 제품군 | **폴라폴리스, 인타록, T/R 싱글, DTY 싱글**. 나열 순서는 판매 우선순위가 아님 | D-012 |
| 추가 판로 | 보드레는 생지·원사 보유 기반 기회. 국내/수출 수요 및 마케팅 범위는 추후 검증 | D-013 |
| 보유 완제품 | 네 제품군 모두 일부 공통 사양/색상의 염색·가공 완료 원단을 선별적으로 보유. 모든 색상/규격에 있다고 홍보하지 않음 | D-014~D-015 |
| 샘플 | 역량 내면 새로운 사양도 적극 검토하되, 신규 원사 구매는 고객 비용 부담을 전제로 예외 검토. 기계 세팅이 필요한 샘플은 비용 청구; 바쁜 시기 수락 어려울 수 있음. 본 발주 시 차감은 건별 협의 | D-016~D-018 |
| 수량 제약 | **'신규 생산 500yd부터 가능' 문구 폐기.** 가용 완제품은 절 단위 공급 가능; 보유 생지 후가공은 공정 최소량; 신규 편직은 세팅/상당한 물량, 신규 원사 구매는 기계 기본 원사 투입량 필요 | D-019 |
| 선호 고객 | 원단 도매·유통업체와 실제 원단을 쓰는 본딩·누빔·PU코팅·봉제 공장. 실제 주요 거래는 소개·업계 인맥·직접 영업에서 시작. 온라인 신규 실거래는 아직 증명되지 않음 | D-020~D-021 |
| 온라인 현재 근거 | GSC에서 광범위한 '편직/섬유공장/원단공장' 검색어가 확인되고 검색 클릭은 루트에 집중. GA4에 제품별/성공 문의 전환 측정 부족. 이메일 접수에 특수·저적합 문의 혼재. 검색어 익명화·전화/카카오 누락 유의 | D-022 |
| 영업 성과 | **A 보유 제품 직접 공급형 = 1차 핵심 성과**, **B 조건부 신규 개발형 = 별도 성장 지표**. C 범위 밖/D 정보 부족은 운영 절차 미확정 | D-023 |
| 거래 가치 | **대량 첫 발주와 반복 거래 모두 중요한 우량 고객**. 샘플만 받고 중단, 무관한 문의, 높은 개발 부담과 소량·일회성이 겹치는 요청은 가치 낮을 수 있음. A/B와 대량/반복은 서로 다른 분류 축 | D-024 |
| 온라인 문의 관리 | 홈페이지 접수는 전용 이메일에 누적되고 블로그·네이버 톡톡·카카오비즈니스는 각 대화 이력만 남음. 별도 통합 관리·진행 상태 추적 없음. 간단 문의 관리 목록은 미승인 제안 | D-025 |
| ERP 통합 관리 방향 | 실제 신규 주문은 기존 ERP 거래처 등록·작업의뢰서·원단 송장 업무에 들어감. **별도 CRM/앱 금지, ERP 내부 온라인 문의관리 페이지 추가를 원함.** 발주·재구매는 ERP 데이터 활용. 최초 문의 수집·연결 키·상세 기능은 미승인 | D-026 |
| 채널 수집 우려 | 이메일·톡톡·카카오·전화 전부 자동 수집이 보장되지는 않음. 사용자는 자동 누락과 기존 대화 재입력 부담을 우려. 카카오 기본 채널은 상담 조회 API 없음, 톡톡은 챗봇 웹훅만 확인, 전화는 별도 시스템 필요. 자동+최소 수동 혼합은 미승인 대안 | D-027 |

## 확정하지 않은 것
- 홈페이지 최종 핵심 카피·사이트맵·정보 구조·문의 폼의 상세 입력값/단계.
- 실제 제품별 대표 SKU, 사진, 중량·폭·가공·가용 재고 표시 정책.
- 온라인 업종별 타깃 우선순위. 제품 중심 검색 유입과 소개/직접영업 신뢰 보강은 검증할 가설.
- ERP 내부 신규 영업문의 페이지의 실제 데이터 모델·권한·상태·수집(수동/자동)과 거래처·작업의뢰서·송장 연결 키, 채널별 전환 측정 KPI는 미승인. **별도 관리 앱/관리표는 대상에서 제외**한다.
- UX 시안·디자인 무드보드/브랜드 시스템, SEO URL·기술 구조, GA4 이벤트 구현 및 배포.

## 다음 작업의 정확한 순서
1. **다음 질문 하나:** 카카오 비즈니스 문의를 현재 일반 카카오톡 채널 관리자센터의 무료 1:1 채팅으로 응대하는지, 공식 상담톡 연동 서비스로 응대하는지 먼저 확인한다. 네이버 톡톡 챗봇 설정도 별도 검증. 사용자는 자동 누락 방지와 대화창에서 ERP로 내용 재입력하는 수고를 크게 우려함(D-027).
2. **외부 API 제약:** 카카오 일반 채널 API에서 1:1 대화 조회 미지원(상담톡 공식 딜러 경로 있음), 네이버 톡톡 챗봇 API 웹훅은 있으나 기존 일반 상담 전체 조회 여부 미확인, 전화는 별도 콜인프라 없이는 내용 자동 수집 불가. 따라서 가능한 자동 접수 대기함 + 최소 수동 추가라는 제안은 아직 미승인. 기존 문의 대화는 원래 채널에 남기고, ERP 내부에서 **가벼운 문의 요약·상태**만 관리하는 설계를 검토한다. 거래처 등록과 작업의뢰서/송장은 실제 생산·출고업무 그대로 유지하고, 실발주 뒤 기존 레코드를 참조할 수 있는 구조로 구분한다. ERP 실제 코드·DB를 읽어 ID/관계·권한을 확인한 뒤에만 상세 설계하며 A/B와 대량/반복 가치 구분을 유지한다.
3. Phase 1 완료 여부 검토: KPI·채널 역할·대표 상품 정보 취합의 우선순위와 필요한 승인 사항을 결정.
4. P2 UX/IA → P3 비주얼/브랜드 디자인 → P4 SEO·AI 검색·콘텐츠 → P5 기술·계측 → P6 통합 검증·명세 승인 → P7 Codex 구현 순서.
