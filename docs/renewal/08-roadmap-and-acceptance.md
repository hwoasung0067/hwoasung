# 08. 단계별 일정·검증·승인 프레임
상태: 제안안. 실 작업 일정/예산/인력/개발 분량 확정 전.

## 설계 선행 순서
P0 현재 근거·코드·고객 조사 기록 → P1 사업 전략 → P2 UX/IA → P3 비주얼/브랜드 디자인 → P4 콘텐츠·SEO/AI 검색 → P5 기술·데이터/계측 → P6 교차 검증·마스터 명세 승인 → P7 Codex 구현/검증/배포 → P8 실제 성과 분석·개선.

각 단계의 핵심 결정은 승인 상태를 기록하며, 기술적인 영향과 데이터·디자인 제약은 초기부터 병행 조사. 단계가 완전히 분리된 사일로가 되지 않게 한다.

## 승인 게이트
- P0: 근거 문서 저장, 확인되지 않은 부분 명시, 운영 코드 미변경.
- P1: 타깃 우선순위, 실제 공급 제품군, MOQ/샘플상담 경계, 주요 KPI 사용자 승인.
- P2: 메뉴·사이트맵·고객 여정·상담 폼·핵심 화면 와이어프레임 사용성 검토.
- P3: 레퍼런스 비교, 승인된 브랜드 디자인 토큰, 홈/리스트/제품 상세/문의 PC·모바일 시안, 프로토타입.
- P4: SKU 콘텐츠 소유·실사·팩트, URL 명세, 인덱싱/콘텐츠 운영 가이드.
- P5: 기술 선택 이유·기존 코드 보호·Firebase 데이터/문의 마이그레이션·GA4 이벤트·배포/보안.
- P6: 각 화면의 사업/UX/디자인/SEO/기술/분석 체크리스트 통과, 충돌·예외/미결 기록, 명시적 개발 승인.
- P7: 기능단위 PR/구현·자동/수동 테스트, 성능/모바일/메타/색인/리다이렉트/보안, 단계별 Preview 및 rollback.
- P8: 기준선 대비 유입 구분, 제품 행동, 문의 적합률, 신규 거래처 효과 측정. 사후 수치 없는 성공 판정 금지.

## 교차 검증 예시
제품 상세: 제품이 팔릴 이유? 구매자도 이해 가능? 실제 사진과 사양? 검색 로봇이 URL/텍스트 인식? 관리자 업데이트 반영? GA4 이벤트 중복 없나?
샘플 문의: 생산 가능 범위를 오해시키나? 폼이 어렵진 않나? 필요한 물량/샘플 정보를 받나? 개인정보 보호? 전송 성공을 측정하나?
디자인: 빠른 로딩·충분한 대비·모바일 조작성·제조 신뢰와 일치하나? 제품/공장 사진을 오도하지 않나?

## 개발 단계 분할 원칙
1. 실 운영 snapshot·백업/테스트 환경.
2. URL 및 SEO/GA4 기반 정비.
3. 홈/제품 탐색/제품 상세 개발.
4. 문의 흐름·제품코드 전달·관리자 편집 기능 조정.
5. 통합 QA·점진 배포·계측 정상화.
각 묶음은 Codex에게 한정된 파일 범위와 완료 기준을 주고, 리뷰 후 후속 구현. 범용 '홈페이지 모두 리뉴얼' 명령 금지.

## 완료/보류 규칙
최종 기능은 승인된 제품 데이터·운영 정책·시안을 기준으로 검수. 미확인 회사 수치나 미완성 사진을 AI 생성으로 임의 대체하지 않는다. 문의 폼 장애·재고 데이터 손상·관리자 인증 실패·색인 손실 징후 시 배포 중단/복구.
